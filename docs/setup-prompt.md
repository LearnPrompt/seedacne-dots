# 从零把自己的 Seedacne Managed Agent 接到 Dots

把下面“主提示词”发给**有终端、浏览器或 computer use 能力的 Codex**。Codex 可以检查并复用[本仓库的模板](../README.md)，不必自行实现桥接服务。完成后，在 Dots 里调用你自己的私有插件。

本流程已完成一次账号实配与视频首测，但不保证所有账号都具备相同资格、界面、模型和工具。不要使用他人的 Agent、API Key 或私人 MCP 地址。

## 需要本人操作或确认的环节

| 标记 | 触发时机 | 本人需要做什么 |
|---|---|---|
| **【本人操作：登录】** | 短信验证码、扫码、设备验证、验证码挑战，或平台要求本人接管时 | 在官方页面完成；验证码和密码不发到聊天里。|
| **【本人当次确认：协议】** | 开通模型、服务或创建资源要求接受协议时 | 看清具体服务、协议和计费方式，再确认。此次实配遇到《方舟平台专用条款》《免责声明》《豆包模型服务协议》，其他账号以当时页面为准。|
| **【本人当次确认：凭据授权】** | 创建专用 Key、把它存入私有 MCP 服务，或扩大已有凭据权限时 | 确认 Key 名称、权限、接收服务的准确网址、存储方式和用途。不能把“帮我配置”当成无限权限；已确认同一范围后不反复询问。|
| **【本人确认：插件访问】** | 安装/连接/OAuth 提示会新增有实质影响的访问权限，或工作区需要管理员批准时 | 核对账户和权限。正常页面查看、草稿填写、代码开发和允许的私有部署无需每步问一遍。|
| **【本人操作或明确授权：费用】** | 充值、订阅、付款或首次生成素材前 | 付款按平台规则由本人完成或给予明确商户、用途和限额授权。生成测试需单独明确范围和预算；不能先跑再报账。|

**这些是遇到时才触发的检查点，不是固定要点五次确认。** 接受协议和新增敏感访问仍须遵守执行平台的当次确认要求。一个检查点只暂停依赖它的动作，其他独立准备工作继续推进。

## 主提示词：整段复制给 Codex

```text
请帮我从零配置我自己的火山引擎 Seedacne Managed Agent，并接入 OpenAI 的 Dots，让我之后能在 Dots 对话中提交图片/视频需求、查询进度、拿到实际成品。

请实际完成配置、实现、私有部署和验证，不要只讲方案。你有权限继续执行必要的只读检查、草稿准备、可逆开发、测试和符合平台规则的私有部署。遇到下述明确需要本人处理或确认的动作再停下，不要每一步都问我。

一、先确认环境
1. 这里的 Dots 指 OpenAI 的 Dots，不是同名产品、Grok Bot，也不是普通 Codex CLI 聊天。
2. 读取当前官方文档并检查可用工具、账号资格、插件能力和登录状态。使用当前账号确实支持的入口，不猜菜单或模型 ID。
3. 优先采用这条已验证的路线：Dots → 自己的私有 MCP 插件 → 方舟 Managed Agents API → Session → 实际图片/视频文件。不要用直接调用视频模型 API 冒充 Managed Agent 接入，也不要把本机 config.toml 配置成功当成云端 Dots 已接通。
4. 优先使用 Sites 支持的私有 MCP 托管与鉴权。如果我附了源码模板，先检查其适用范围再复用。若账号没有 Sites/私有插件能力，先明确缺少什么和可行替代，不要原样把依赖 Sites 鉴权的模板公开部署到其他平台，不要自行付费购买替代服务。

二、配置方舟
1. 用允许的浏览器或 computer use 打开我自己的火山方舟控制台，先查看已有资源，能安全复用就复用，避免重复创建。
2. 选择视觉创作专用 Agent。传播名称使用 Seedacne Managed Agent；控制台可能显示 Seedance Managed Agent，程序字段和 API 名称遵照当前官方文档。
3. 按当前文档配置 base_agent=ultra_vision_agent_preview、reasoning_effort=high，以及该类型要求的基础工具集、多模态工具集和必选工具。启用视频生成时绑定实际可用的视频模型；图片生成也要绑定实际可用的图片模型。启用 general_search 时按文档关闭冲突的 web_search。
4. 主模型、图片模型和视频模型都从我账号实际可选项中确认。某模型需要开白时先检查其他官方支持的可选模型，不能保证所有账号都能用同一个型号；也不能通过换账号绕过限制。
5. 创建或复用专用云端 Environment。没有需要时不添加初始化脚本、额外依赖、第三方存储或其他凭据。记录真实 Agent ID、Environment ID、模型和工具配置。
6. 不要为了接入先让我买 Agent Plan。先查清当前服务的开通条件、按量计费方式及余额需求；免费开通不等于免费使用，充值也不等于 Agent 已接通。

三、实现并部署私有 MCP
1. 服务端配置 ARK_API_KEY、ARK_AGENT_ID、ARK_ENVIRONMENT_ID；API Base URL 按当前官方地域文档核对。密钥只能进入受支持的服务端秘密变量机制，不写入前端、源码、公开配置、截图、终端输出或工具参数，也不要让我把 Key 发到聊天里。
2. 优先创建接入专用 Key，在页面允许的范围内只授权所选主模型、图片模型和视频模型；不默认授权未来新增资源，无需使用的推理接入点不勾选。若该权限设置不能限制 Managed Agent 资源本身，明确实际边界，不声称它具有不存在的资源级隔离。不得修改、删除或扩大我其他 Key 的权限。
3. 提供连接检查、参考图上传及查询、新建任务、原会话继续修改、按轮查询任务和产物的工具。工具要有明确的输入 schema、费用说明和真实读写标记，名称可清楚易懂，不需要逐个复制全部方舟 API。
4. 任务和参考图属于发起用户；校验访问权限。每个新需求用稳定 request_id，每次原会话修改用新的稳定 turn_id，在持久存储中防重复提交与并发冲突。网络超时或提交结果不明时保留任务和 Session ID，先查询原任务，不自动换编号重发，不自动抽卡重做。
5. 遵循 Session 事件协议：发送前建立事件流并等待就绪，处理断线补查、stop_reason、requires_action、重调度和工具错误。HTTP 200、idle、连接关闭或 Agent 自称完成，都不能单独视作成功。
6. 参考图使用 OpenAI fileParams 附件对象，先上传方舟并挂载到 Session；消息使用挂载返回的 file_id。只允许经过核验的临时下载 hostname，不能把本机路径当作云端可读路径，不保存临时签名 URL。原会话修改复用同一 Session，等待上一轮结束；保存每轮事件边界与产物快照，不能把上轮终态或旧文件当新结果。通过 Files API 查询实际产物，按 after/has_more 处理分页及注册延迟；临时下载链接要及时下载。向我交付真实可打开的文件，不只给沙箱路径、代码或生成成功的文字。
7. 若复用随附模板，注意它依赖 Sites 的鉴权网关和可信用户身份 Header。不能通过相信客户端自报的 Header 实现公共服务鉴权。保持服务仅本人可访问，不扩大到工作区或公开网络受众。
8. 使用 Sites 当前支持的 MCP/插件工作流。私有服务发布后先检查是否已生成并连接对应插件，避免再创建一个重复插件；若需要安装或 OAuth，再按当前支持的入口完成。
9. 部署前跑相应测试和构建，检查最终 diff。使用 Cloudflare Workers 时不要使用不支持的 redirect:error；用 manual 并拒绝未经核验的重定向，避免把 Authorization 带到其他域名。环境变量变更后要应用到线上并验证，不能只写进本地文件。

四、把需要我处理的环节单独标出来
【本人操作：登录/验证码/付款】把正确官方页面准备好，让我直接完成；不要收集我的密码、短信码或支付信息。
【本人当次确认：接受协议】先展示当前具体协议、开通对象和计费说明，再请求本次确认。不要代勾选后再问。
【本人当次确认：凭据授权】先准备好专用 Key 名称、准确权限和将保存密钥的私有服务网址，再请求授权创建及安全存储。不要先读取其他 Key 或先转存后补问。
【本人确认：插件新权限】说明账户、权限和用途；遇到管理员限制不要绕过。
【本人明确授权：付费试跑】先完成所有不花生成费用的工作，再提出具体测试规格、调用范围和预算。若无法强制封顶费用，要明说，不能把一次提交说成固定总价。
没有遇到这些检查点就继续执行；已授权且范围未变的动作不要重复询问，平台明确要求当次确认的情况除外。不要用询问代替你能完成的独立准备工作。

五、分层验收
第一层：本地测试/构建通过，并验证鉴权、用户任务隔离、稳定编号防重、错误处理和密钥隐藏。这不等于线上接通。
第二层：实际通过安装的 MCP 插件做只读连接检查，再用服务端 Key 读取我自己的 Agent 和 Environment。记录真实返回结果，不仅检查变量存在。这不等于视频已经生成。
第三层：我明确授权后，在 Dots 对话里只提交一次约 5 秒、9:16、720P 的无品牌奶茶测试视频；不要自动制作海报或第二个版本。固定新的 request_id，取回真实 MP4，测量尺寸、帧率和实际时长，检查能否完整解码、画面明显问题及音频情况。若做了裁剪/转码，分别记录生成原片和导出文件；没听音频就不要声称听过。无法取得计费数据时如实写无法获取，不编估价。
保留未达标项；“拿到视频”和“画面完全符合需求”分别报告。模型不支持所需时长时先说明，不悄悄改成长片反复生成。

六、交付
交付我自己的插件名称、服务/MCP 地址、非敏感配置文件、可移植源码和简短回执。回执区分本地校验、线上只读验证、Dots 实际调用和最终素材检查。密钥不出现在交付中。
给我一段日后直接发给 Dots 的创作提示词。明确后续素材调用按实际用量计费，哪些环节还未验收。如果受账号或平台限制，给出具体证据和唯一必要的下一步，不把草稿、构建或部署状态冒充接通成功。

参考官方文档：
https://docs.volcengine.com/docs/ark/visual-creation-agent?lang=zh
https://learn.chatgpt.com/docs/dots
https://developers.openai.com/plugins/quickstart
https://developers.openai.com/plugins/build/mcp-server
```

## 可直接使用的授权回复示例

这些回复应在 Codex 展示具体对象、权限和页面之后发送，不是提前对未知服务的无限授权。

**协议：**

> 我已阅读你列出的当前协议，同意为我这次指定的模型和 Agent 开通服务；按页面所示完成开通并创建。本次不提交素材生成。

**专用 Key 与私有服务：**

> 授权创建你刚展示的专用 Key，保持所列模型范围和零额外接入点，并安全写入你刚展示的、仅我可访问的私有服务的服务端秘密变量。允许 Dots 在我请求时调用；不改其他 Key，本次先只读验证。

**首次生成：**

> 允许使用我的专用插件提交一次约 5 秒、9:16、720P 的奶茶视频测试，不做其他版本或海报。预算按我们刚确认的范围执行；不确定会超出时先停止。失败后先查原任务，未经确认不重新生成。

测试预算应由使用者自行填写和确认，不能沿用别人的额度或付费授权。后续已明确授权的同一任务无需再次问同样的问题。

## 这次实配可证明什么

- 维护者账号实际完成了专用 Agent、云环境、受限 Key、私有 MCP 与插件连接。
- 只读调用成功读取 Agent 与 Environment；当时 v0.1 的 10 项离线测试通过。
- 用户随后在 Dots 中完成了奶茶视频首测并提供截图。本轮又通过原任务插件查询核到 `end_turn`、任务结束、无工具错误。没有再次生成。
- 本仓库收录用户提供的成片与对话截图，独立使用 ffprobe 核到 720×1280、24fps、容器时长 5.056 秒，并通过 ffmpeg 完整解码。截图记录奶感偏弱、杯身略收底等偏差；本次没有重新生成或试听音频。这证明了实际交付链路跑通，不证明视觉需求全部达标。详见 [实测案例](demo.md)。
- 视频生成计费明细未取得；Agent token/运行时长不等于完整视频账单，不据此推算固定成本。

**命名说明：**本项目的对外名称为 Seedacne Managed Agent；控制台、模型、工具和 API 中可能仍使用 Seedance。保留官方实际标识，不自行改写可执行字段。
