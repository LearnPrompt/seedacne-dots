# 排障说明

先保留原 `request_id` 和可取得的 Session 信息。查询、下载已有产物与只读诊断可以继续；不要把排障变成重复付费生成。报告错误时不附 Key、账号信息或含访问能力的下载链接。

| 现象 | 先检查 | 下一步 |
|---|---|---|
| 没有 Sites 或私有插件入口 | 当前工具能力、账号资格、工作区限制与官方文档 | 明确具体缺项；不要把本机 MCP 连接当作云端 Dots 接通，也不要直接换公共主机裸部署 |
| 401 / 无法识别调用者 | 插件是否以正确账号连接；请求是否经过 Sites 鉴权网关 | 核对私有 Site 访问范围和连接状态；不能让客户端自行填写身份 Header |
| 配置显示就绪，但不能读到资源 | 服务端 Key、Agent/Environment 是否属于正确账号及地域 | 调用 `seedance_connection_status` 并设置 `verify_remote=true`；变量存在不等于上游授权成功 |
| 模型不可选或提示无权限 | 当前账号开通资格、支持的模型/工具集、是否需要开白 | 选择官方支持且用户可用的配置，必要时报告缺少权限；不绕过限制或自动购买 |
| 生成未启用 | 线上 `GENERATION_ENABLED` 是否仍为 `false` | 完成只读验收并取得生成授权后才启用；核对线上已应用配置 |
| 参考图下载域名未获允许 | 错误中只显示的 hostname、当前宿主文件来源 | 将核验后的精确主机名写入 `REFERENCE_ALLOWED_HOSTS`，重新部署原已保存版本以应用配置，再传附件；不同区域可能使用不同 hostname，保留原名单并追加已核验项，不要允许任意域名或输出签名查询串 |
| 参考图链接过期 / 403 / 410 | 附件是否仍有有效下载授权 | 重新选择原附件，由宿主传新临时 URL；不要猜 file_id 刷新接口 |
| 原任务修改被拒绝 | 上轮是否运行、需确认、终止或提交结果不明 | 先查原轮；不能新建另一个 Session 冒充续接 |
| 修改后仍拿到旧文件 | 查询的 turn_id 与该轮产物登记 | 默认查最新轮；旧产物不算本轮成功，等本轮文件注册 |
| 新 Session 无产物时查询报错 | 桥接是否为 0.2.1 或更新版本 | 已兼容上游空文件列表的 JSON null；返回空列表不等于任务成功 |
| `recoverable_before_submission=true` | 同一原任务是否确证从未发送 user.message，且 Session idle | 使用原 request_id 和完全相同参数调用 create_task 恢复，不创建新会话；任何发送边界已写入则不能走此恢复 |
| 创建任务超时 / `needs_review` | 原任务的持久记录、Session 和事件 | 用原编号查询；创建结果不明时不自动再次提交，不换编号重试 |
| 同一编号绑定另一需求 | 是否修改了已提交需求的提示词 | 先核清原任务；只有确属新的且已授权的需求才使用新编号 |
| `idle`，却没有成品 | `stop_reason`、工具错误、事件和 Agent 消息 | 不能仅据 `idle` 报成功；核查 `end_turn` 与实际产物。需要外部动作/重新调度时按当前官方协议诊断，不把重新生成当恢复机制 |
| Agent 说已生成，却拿不到文件 | Files API 注册延迟、分页、文件类型，以及返回的 `not_ready` | 对同一任务重新查询产物；`processing` 稍后再查，`failed` 按失败如实报告，不自动重做；内部沙箱路径不是可交付文件 |
| 下载地址失效 | 是否使用过期临时链接 | 从原任务重新取得有效产物链接，及时下载；不重新生成 |
| 实际文件与 Brief 不符 | 文件元数据、抽帧、画面和必要的试听 | 分别报告链路结果与质量偏差；记录裁剪/转码，不自动重做 |
| 只能拿到 Agent tokens | 是否有完整模型与视频计费记录 | 标记无法获取完整费用，不用 tokens 估算整项视频账单 |

## 本地与部署问题

- `node:sqlite` 不可用：使用支持该内置模块的 Node.js；本模板在 Node.js 24 上测试。
- `DB` 或表不存在：核对 Sites 的 D1 `DB` 绑定及部署迁移。按顺序应用全部 `drizzle/` 迁移，包括 v0.2 新增表；不要重建或清空旧 jobs 表，不要在请求处理时临时建表。
- 构建完成但线上行为没变：核对部署的构建产物、当前部署版本和服务端配置；重新验证实际安装插件的调用。
- Cloudflare Workers 的重定向错误：模板使用 `redirect:manual`，拒绝非预期重定向。不要改成自动跟随并将 `Authorization` 发往其他目标；按官方文档核对固定上游 URL。

## 平台与实现边界

模板默认使用方舟中国北京 API，未验证其他地域。v0.2 提供参考图上传与原 Session 续接；支持格式/大小及文件宿主要求见 [使用说明](references-and-turns.md)。音频/视频参考上传与独立生成参数尚未实现。

Sites 网关负责认证并注入可信的 `oai-authenticated-user-id`。若迁移至其他平台，必须先设计等价的身份认证、授权和用户任务隔离。直接接受公网客户端自报 Header 会让用户身份可伪造，不能原样上线。

需要扩大权限、变更接收凭据的服务或新增付费调用时，按 [授权清单](authorizations.md)准备具体对象并取得相应授权；已授权同一范围的诊断无需反复询问。
